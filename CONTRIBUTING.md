# Contributing to Glassport

Start with a reproducible observation: which action failed, what happened instead, and which part of the local browser or MCP workflow was involved. Include the operating-system and dependency versions when they explain the behavior, without identifying a private device, account or network.

Use a separate branch and keep changes focused. Follow AGENTS.md, run the relevant checks listed in README.md, and state whether verification used synthetic local data or a physical iPad. A mock or a successful native dispatch does not prove the intended on-device result. For a device change, describe the observed screen and data-transfer behavior using synthetic content.

Do not attach private screenshots, copied app content, device configuration, pairing records, local paths, addresses, account identifiers or credentials. Doctor and diagnostic output can contain private metadata, so inspect and sanitize them before sharing. Submit a pull request with the problem, resulting behavior, validation and any remaining limits. Retain the applicable licenses and third-party notices when modifying or distributing native code or bundled dependencies.
